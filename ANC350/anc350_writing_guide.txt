[cite_start]您的目标是编写一个Python程序，它能可靠地控制ANC350位移台。我们将严格遵循《指南》中的“数字孪生”（面向对象封装）思想 [cite: 2708][cite_start]，但使用 `anc350res_8h.html` 中定义的具体DLL函数，而不是《指南》中示例的PyVISA/SCPI [cite: 2694]。

以下是您的Python代码需要完成的任务步骤分析：

---

### 零、 运行环境准备 (代码运行的前提)

在编写Python代码之前，您必须确保目标计算机（即连接ANC350的电脑）满足两个条件：

1.  [cite_start]**硬件驱动已安装**：ANC350的底层USB驱动（或以太网驱动）必须已安装，确保Windows设备管理器能看到该设备 [cite: 600, 2744]。
2.  **DLL文件可用**：您必须拥有 `anc350v4.dll` 文件，并将其放在Python脚本可以访问的路径下（例如，与您的Python主脚本放在同一个文件夹中）。

### 第一步：初始化、发现与连接 (程序的启动)

这是程序的起点，目标是让Python与 `anc350v4.dll` 对话，并获取对硬件的控制“句柄”(Handle)。

1.  **加载DLL**：程序需要使用Python的 `ctypes` 库来加载 `anc350v4.dll` 文件。
2.  **定义函数原型 (关键)**：您必须告诉 `ctypes` 库，`anc350res_8h.html` 中每一个您想用的C函数，它们的**参数类型** (`.argtypes`) 和**返回类型** (`.restype`) 是什么。
    * *例如*：对于 `ANC_discover`，您需要告诉Python它需要一个`ANC_InterfaceType` (整型) 和一个指向 `Uit32` (无符号整型指针) 的参数，并且它返回一个 `Int32` (整型)。
3.  **发现设备**：调用 `ANC_discover` 函数，询问DLL在所有接口（USB、TCP等）上共发现了多少台ANC350设备。
4.  **连接设备**：程序将选择一台已发现的设备（例如，第0台），并调用 `ANC_connect` 函数。
5.  **获取句柄**：如果连接成功，`ANC_connect` 会返回一个 `ANC_Handle` (设备句柄)。这个句柄是后续所有控制命令的“通行证”，必须被安全地存储起来。

> [cite_start]**对应《指南》**：这一整套流程应该被封装在您要创建的 `ANC350Controller` 类的构造函数 (`__init__`) 中 [cite: 2714]，实现自动连接。

### 第二步：配置轴参数 (运动前的准备)

连接成功后，不能立即移动。您必须先配置位移台的运动参数，告诉它“如何移动”。

1.  [cite_start]**使能轴输出 (安全开关)**：这是**最关键**的一步。默认情况下，轴的高压输出是关闭的 [cite: 1027, 1029]。您必须调用 `ANC_setAxisOutput` 函数，将 `enable` 参数设为 `True` (或 1)。
2.  [cite_start]**选择执行器**：(如果需要) 您可能需要调用 `ANC_selectActuator` 来告诉控制器该轴连接的具体位移台型号（例如手册中提到的 ANPx101res [cite: 1088]），以加载正确的运动参数。
3.  **设置运动模式参数**：根据您的需求选择一种模式并设置其参数：
    * **开环步进 (Stepping)**：设置 `ANC_setAmplitude` (电压) 和 `ANC_setFrequency` (频率)。
    * [cite_start]**闭环扫描 (Auto-Move)**：设置 `ANC_setTargetPosition` (目标位置)。您可能还想设置 `ANC_setTargetRange` (目标范围)，它定义了“到达目标”的精度范围 [cite: 1227]。

> [cite_start]**对应《指南》**：这些配置步骤应该被封装为 `ANC350Controller` 类中清晰的方法，例如 `setup_axis(axis, voltage, freq)` 或 `set_target(axis, position)` [cite: 2711]。

### 第三步：执行运动 (发起动作)

配置完成后，您可以命令位移台开始移动。API提供了几种不同的运动方式。

1.  [cite_start]**单步移动**：调用 `ANC_startSingleStep`。这在GUI中对应“单击步进”按钮 [cite: 996, 1867]。
2.  [cite_start]**连续移动**：调用 `ANC_startContinousMove`。这对应“按住不放的连续移动” [cite: 997, 1867]。
3.  [cite_start]**自动逼近 (用于扫描)**：调用 `ANC_startAutoMove`。这是执行自动化扫描的核心命令。它告诉位移台：“开始移动，直到你到达在第二步中设置的那个目标位置为止。” [cite: 2092]。

> [cite_start]**对应《指南》**：在《指南》的核心扫描循环 [cite: 2731] 中，您将主要使用 `ANC_setTargetPosition` (第二步) 和 `ANC_startAutoMove` (第三步) 的组合。

### 第四步：状态轮询与反馈 (等待与确认)

这是一个至关重要的步骤，尤其是在自动化扫描中。调用 `ANC_startAutoMove` 后，程序**必须等待**位移台完成移动，才能进行下一步（例如：采集光谱数据）。

1.  **创建等待循环**：程序需要进入一个循环，反复向控制器查询状态。
2.  **查询状态**：在循环中，调用 `ANC_getAxisStatus` 函数。
3.  **检查标志位**：`ANC_getAxisStatus` 会返回多个布尔值。您需要检查 `moving` 标志位。
    * 如果 `moving` 为 `True` (或 1)，说明位移台还在移动，循环继续。
    * 如果 `moving` 为 `False` (或 0)，说明移动已停止。
4.  [cite_start]**(可选) 获取位置**：在循环中或循环结束后，您可以调用 `ANC_getPosition` 来获取并显示当前的精确位置，用于在GUI上更新读数 [cite: 913]。

> [cite_start]**对应《指南》**：这个“等待循环”是一个“耗时任务” [cite: 2728][cite_start]。在GUI程序中，这个循环**必须**在一个单独的 `threading` 线程中运行 [cite: 2728]，否则您的整个用户界面将会卡死。

### 第五步：断开与清理 (程序的退出)

当您的扫描任务完成或用户关闭程序时，必须安全地释放硬件。

1.  [cite_start]**设置安全状态**：(推荐) 调用 `ANC_setTargetPosition` 将位移台移回“0”位或安全位置 [cite: 2734]。
2.  **断开连接**：调用 `ANC_disconnect` 函数。
3.  **释放句柄**：`ANC_disconnect` 会释放您在第一步中获得的 `ANC_Handle`，允许其他程序访问该设备。

> [cite_start]**对应《指南》**：这个清理步骤应该放在一个 `finally` 块中 [cite: 2734]，以确保**无论程序是正常结束还是中途出错**，硬件连接都一定会被安全释放。

---

### 总结：代码的逻辑流程

您的主程序（或扫描线程）的逻辑将是：

1.  `__init__`： (自动) 加载DLL -> `ANC_discover` -> `ANC_connect` -> 获取 `ANC_Handle`。
2.  `setup_scan`： 调用 `ANC_setAxisOutput(True)` -> `ANC_selectActuator` -> ...
3.  `scan_loop`： (循环开始)
    1.  计算下一个目标点 `pos`。
    2.  调用 `ANC_setTargetPosition(pos)`。
    3.  调用 `ANC_startAutoMove`。
    4.  (进入等待循环) 反复调用 `ANC_getAxisStatus`，直到 `moving` 标志位变为 `False`。
    5.  (移动完成) 调用其他仪器的代码（例如采谱）。
    6.  保存数据，更新图表。
    7.  (循环结束)
4.  `cleanup` (在 `finally` 中)： 调用 `ANC_disconnect`。

是的，您提供的信息确实包含了网络控制的部分，并且您的想法——先搜索、再确认连接方式、然后控制——是完全可行且正确的，这正是DLL API所支持的工作流程。

让我们来分析一下您提供的信息是如何支持这一点的：

网络控制是支持的:


硬件手册 (PDF)：明确提到了ANC350后面板上有一个**(可选的)以太网端口** 。手册还提到了可以通过DAISY软件配置IP地址、子网掩码和网关 ，这都证明了网络控制是设备的一个功能。





DLL API 文档 (anc350res_8h.html)：

ANC_discover 函数的说明提到它可以搜索 "USB and LAN" 上的设备。

ANC_discover 函数接受一个 ANC_InterfaceType 参数，您可以指定搜索 IfTcp (仅网络)、IfUsb (仅USB) 或 IfAll (所有接口)。这明确表明DLL支持发现网络设备。

还有一个 ANC_registerExternalIp 函数，用于手动注册不在同一子网中的网络设备，进一步证明了网络控制能力。

可以搜索并识别连接方式:

工作流程: 您应该先调用 ANC_discover(IfAll, ...) 来查找所有连接的设备。

识别: 找到设备后（假设发现了 N 台），您可以循环调用 ANC_getDeviceInfo(devNo, ...) 函数（devNo 从 0 到 N-1）。

关键信息: ANC_getDeviceInfo 函数会返回一个 address 参数。根据文档说明，这个参数会返回：

设备的IP地址字符串（例如 "192.168.1.100"），如果它是通过网络连接的。

字符串 "USB"，如果它是通过USB连接的。

确认: 通过检查返回的 address 字符串，您的程序就可以在调用 ANC_connect 之前准确地知道这台设备是用哪种方式连接的。

连接与控制:

一旦您通过 ANC_getDeviceInfo 确认了您想要控制的设备（无论是通过序列号、ID还是连接方式识别），您就使用它的设备编号 (devNo) 调用 ANC_connect。

DLL库会在内部处理是建立USB通信还是TCP/IP通信。您后续调用 ANC_setTargetPosition, ANC_getPosition 等函数时，使用的方法是完全一样的，无需关心底层是USB还是网络。

总结:

您完全可以按照您的想法来做：

使用 ANC_discover 搜索所有连接的ANC350控制器。

遍历搜索结果，使用 ANC_getDeviceInfo 获取每台设备的详细信息，特别是通过 address 字段判断它是通过网络 (IP 地址) 还是 USB ("USB" 字符串) 连接的。

根据您的需要（例如，匹配特定的IP地址或仅仅是找到第一个网络设备），选择正确的设备编号 devNo。

使用这个 devNo 调用 ANC_connect 来建立连接。

之后使用返回的 ANC_Handle 进行控制，无需再区分USB或网络。
